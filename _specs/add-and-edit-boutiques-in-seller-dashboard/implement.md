## Deviations from plan

1. **Create → same page reloads as the new boutique** (AC-32). Plan Step 8 said
   "Create → id → `replaceWith(id)`". A route replacement completes the list's
   `await` at that moment, so later edits to the new boutique would not reload
   the list (AC-37). Instead the bloc switches the same page to the new id and
   loads it in view mode (Inactive); `didChange` stays `true` and the list
   reloads when the page closes. No file outside the plan was needed; the
   `openCreated` navigation value was dropped.
2. **Owner-approved review mitigations** (review.md follow-ups 3–5), all inside
   the planned files:
   - P-1 / S-5: `PickedImageFile.size` is checked before any read; the first 16
     bytes give the type; width / height come from
     `ImmutableBuffer.fromFilePath` + `ImageDescriptor.encoded` (no pixel
     decode), both disposed. Replaces `decodeImageFromList` named in Step 12.
   - P-2: previews use `cacheWidth` / `memCacheWidth` sized to the tile; only
     the active language tab is built.
   - P-3: text lives in page controllers and reaches the bloc only on tab
     change, copy and save (`BoutiqueEditorTextSynced`); `withTranslation`
     shares every unchanged translation between `form` and `saved`.
3. **Minor review notes applied** (advisory, inside planned files): S-2 (Quill
   document limited to bold / italic / underline / H2; links and embeds dropped
   both ways), S-3 (write use cases refuse an empty shop id), S-4 (shop checked
   before save and before each upload; mismatch closes the page), S-6 (magic
   bytes), S-8 (exact pins), P-4 (HTML converted only at load and sync; empty
   via `document.isEmpty()`; controllers disposed), P-6 (queue cleared in
   `close()`; `isClosed` checked after every await), P-7 (languages and
   record fetched in parallel; languages cached for the session), P-8 (no
   `withData`), C-2 (clear always runs), C-3 (checker in content page), C-4
   (clear resets status to `init`; the tab shows the spinner for `init`).
   **Not applied:** P-8's per-pick limit (no limit exists on the website; not
   in the plan), P-5 per-file progress (a count is shown on the Add tile
   instead).
4. **Shared UI pieces** (`BoutiqueSectionCard`, `BoutiqueColors`,
   `BoutiquePreviewImage`) live in `boutique_availability_section.dart`, because
   the plan names no separate shared file.
5. `missingBoutiqueShopFailure` is declared in `create_boutique_usecase.dart`
   and imported by the update and change-status use cases.
6. **AC-35 / AC-36 partly met** — as recorded in `plan.md > Recorded deviation`:
   the red box and the save error show the backend `message`, not every
   `detailed_error` entry.
7. The list card's existing `'Active'` / `'Inactive'` text and raw HTML
   description are unchanged (list layout is out of scope, spec OQ-11).
