# Secret scanning

The repository is checked for credentials in two places.

| Where | What it scans | Blocks? |
| --- | --- | --- |
| `.githooks/pre-commit` | your staged changes, before the commit is written | yes, on your machine |
| `.github/workflows/gitleaks.yml` | every file in the checked-out commit | yes, the CI job fails |

Both use the same rule file, [`.gitleaks.toml`](../.gitleaks.toml): the default
gitleaks rules plus the credential shapes this project uses (Agora, Pusher,
SmartLook, the media server, Sentry DSN, live payment keys, `Bearer` tokens,
keystores, `.env`, `key.properties`).

## Turn the hook on

Once per clone:

```sh
git config core.hooksPath .githooks
```

Then install gitleaks:

| OS | Command |
| --- | --- |
| Windows | `winget install gitleaks` |
| macOS | `brew install gitleaks` |
| Linux | download from <https://github.com/gitleaks/gitleaks/releases> |

If gitleaks is missing, the hook prints a warning and lets the commit through.
It never blocks you for not having the tool installed. CI runs the same scan, so
a secret is still caught before it reaches the base branch.

## When the hook stops a commit

1. Take the value out of the code.
2. Put it in `.env` (git ignores it) or in a GitHub Actions secret.
3. **Rotate the value.** It was written to a file you were about to share, so
   treat it as burned.

If the finding is wrong, add an entry to `.gitleaks.toml` with a written reason.
Do not reach for `git commit --no-verify` — the next person hits the same
finding and has no idea whether it was checked.

## Where secrets belong

| Kind | Home |
| --- | --- |
| Backend URLs, public ids | `.env`, and plain text in the deploy workflow |
| API keys, tokens, DSNs | GitHub Actions secret, read as `${{ secrets.NAME }}` |
| Signing keystore | GitHub Actions secret, base64, decoded during the build |
| Anything a user's device must hold | `flutter_secure_storage`, never `SharedPreferences` |

`.github/workflows/deploy.yml` writes `.env` during the build. Only public URLs
are literal in that file; every credential comes from a secret.

## Known exceptions

`.gitleaks.toml` allows two things, each with the reason written next to it:

- **Firebase config generated by the FlutterFire CLI** — `lib/firebase_options.dart`,
  `google-services.json`, `GoogleService-Info.plist`. These keys identify the
  app; they authorise nothing on their own.
- **The Google Maps client key** — in `AndroidManifest.xml` and
  `AppDelegate.swift`. It is compiled into the APK and the IPA, so keeping it
  out of the repository would change nothing.

Both depend on a control that lives outside this repository: the keys must be
restricted in the Google Cloud console, by package name + SHA-1 on Android and
by bundle ID on iOS. **Check that this is actually set.** Without it, anyone can
pull the key out of a released build and bill it to us.

## History

CI scans the checked-out files, not the whole history, on purpose.

A scan of the full history (668 commits) finds 17 credentials committed between
2023 and 2026, and later removed from the files. Scanning history on every run
would fail every build and teach everyone to ignore the job.

Removing a value from a file does **not** remove it from git. Anyone with a
clone still has it. So every credential below has to be treated as burned and
rotated:

| Credential | First committed |
| --- | --- |
| The whole `.env` file, twice | 2024-09-30, 2025-05-31 |
| Gemini API key | 2025-05-31 |
| A JWT and a `Bearer` token in `main.dart` | 2024-10-12 |
| Three different Sentry DSNs | 2024-01 → 2026-07 |
| SmartLook key | 2026-07-11 |
| Media server API key | 2026-07-11 |
| Pusher key | 2026-02-21 |
| Agora App ID | 2026-02-21 |
| Two secrets in `android/app/build.gradle` | 2023-10, 2023-12 |
| Five Google / Firebase keys | 2023 → 2026 |

Run the history scan yourself with:

```sh
gitleaks git . --config .gitleaks.toml --redact
```

Rewriting history (`git filter-repo`) would remove the values, but it changes
every commit hash and forces everyone to re-clone. Rotating the credentials is
cheaper and gives the same protection, because a rotated key is worthless to
whoever has the old clone.
